# 検証スクリプト

入口：[AGENTS.md](../AGENTS.md)　／　手順：[ワークフロー](../docs/workflow.md)

`check_spec.py` は、仕様書の形を機械的に確かめる。Python 3 だけで動き、追加のインストールは要らない。

```
python3 tools/check_spec.py                # リポジトリ全体（リンク、入口からの到達、templates/ と specs/ の仕様書）
python3 tools/check_spec.py path/to/spec.md # 指定した仕様書だけ
```

## 確かめること

| 対象 | 内容 | 扱い |
|---|---|---|
| すべての Markdown | 相対リンクの先がある | エラー |
| すべての Markdown | AGENTS.md からリンクでたどれる | エラー |
| 仕様書 | 0〜13 の節がそろい、順に並んでいる（短い形は 0〜5、7、9、11〜13） | エラー |
| 仕様書 | 0 の状態が 骨子／たたき台／レビュー済み／承認済み のいずれかで、版が書かれている | エラー |
| 仕様書 | 要件 ID の形が正しく、重複していない | エラー |
| 仕様書 | 要件の優先度が Must／Should／Could／Won't のいずれか | エラー（骨子では見ない） |
| 仕様書 | 要件に完了の条件が書かれている | エラー（骨子では見ない） |
| 仕様書 | 承認済みなら版が 1.0 以上 | エラー |
| 仕様書 | 要件と完了の条件に「適切に」「速やかに」「使いやすく」「など」がない | 警告 |
| 仕様書 | 要件 ID が 11（完了の条件）に出てくる | 警告（骨子では見ない） |
| 仕様書 | 承認済みなのに【未決: …】【仮定: …】が残っている | 警告（ユーザーが残すと決めたものは可） |

エラーが 1 件でもあると終了コードが 1 になる。

## 確かめないこと

要件同士の矛盾、例外の抜け、完了の条件が本当に判定できるか、用語の揺れは見ない。これらは自分のチェックとレビュワーで確かめる。
