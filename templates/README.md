## 人にも AI にも読める形にする

できあがった仕様書は、人が読んでも AI が読んでも同じ内容が伝わる形にする。

| 決まり | 理由 |
|---|---|
| 1 の先頭に一文の要約を書き、0 に文書一覧を置く | 人は全体をつかめ、AI は必要な文書だけを選んで読める |
| 要件・項目・エラーは表に、流れと背景は文章に書く | 表は AI が 1 行ずつ拾え、人が抜けを見つけられる |
| 図（Mermaid）には、同じ内容を文章か表でも書く | 図だけでは AI が読み違え、表示できない環境の人も読めない |
| 色、太字、位置（「上の表」「前述」）だけで意味を伝えず、節の番号と ID で指す | 文書を分けたり一部だけ読んだりしても参照先が分かる |
| 略語と社内の言葉は 3（用語）に書き、同じものを別の言葉で呼ばない | 人も AI も、言葉が違えば別のものと読む |
| 画像（スクショ）で示した内容は、項目名と値を文章でも書く | AI は画像を読めない場合があり、人も検索できない |
| 1 つの節は 1 画面で読める長さを目安にし、超えたら文書を分ける | 人は読み切れ、AI は関係する節だけを読める |

## 使い方の決まり

- Claude Docs で作るときは、テンプレートの見出しと表をそのまま文書に写す。リポジトリに置くときはファイルを写す。
- 山かっこ `<…>` と「例」の行を置き換え、HTML コメントは消す。
- 節は消さない。当てはまらない節は「該当なし（理由）」、別の文書に書いた節は「→ リンク」と書く。
- 文書を分けたら、本体の 0 の「文書一覧」に行を足し、分けた文書の先頭に本体へのリンクを置く。
- テンプレートのもとにした外部の作法は [出典の一覧](../docs/references.md) にある。
- テンプレートを直したいときは、[ワークフロー](../docs/workflow.md) の「工房の整備」に従う。
